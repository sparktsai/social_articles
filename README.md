# social_articles

本專案用來備份與整理各社群平台的貼文與文章草稿，讓同一系列主題在不同平台的版本能以一致的目錄與檔名規則保存。

## 專案結構

專案採三層結構：

1. 系列主題
2. 社群網站
3. 系列文章草稿

```text
social_articles/
├── TI_TraceID/
│   ├── Linkedin/
│   │   └── LTI-01.md
│   ├── X/
│   │   └── XTI-01.md
│   └── Medium/
│       └── MTI-01.md
└── BRA_BackendRoadmap/
    ├── Linkedin/
    │   └── LBRA-01.md
    ├── X/
    │   └── XBRA-01.md
    └── Medium/
        └── MBRA-01.md
```

## 系列主題目錄命名

第一層目錄代表系列主題，命名格式如下：

```text
{縮寫}_{全名}
```

範例：

```text
TI_TraceID
BRA_BackendRoadmap
```

命名原則：

- `{縮寫}` 使用大寫英文字母，作為該系列文章的短代碼。
- `{全名}` 使用可讀性高的英文名稱，可使用 PascalCase 或清楚的英文單字組合。
- 縮寫與全名之間使用底線 `_` 分隔。

## 社群網站目錄

第二層目錄代表草稿要發布的社群網站。目前包含：

```text
Linkedin/
X/
Medium/
```

如果未來新增其他平台，請在系列主題目錄底下建立新的平台目錄，並沿用相同的文章檔名規則。

## 系列文章檔案命名

第三層檔案為實際文章草稿，命名格式如下：

```text
{社群網站第一個字母}{系列主題縮寫}-{系列文序號2位}.md
```

範例：

```text
LTI-01.md
XTI-01.md
MTI-01.md
LBRA-01.md
```

命名說明：

- `{社群網站第一個字母}`：使用平台名稱第一個大寫字母。
  - `L` = Linkedin
  - `X` = X
  - `M` = Medium
- `{系列主題縮寫}`：使用第一層系列主題目錄中的縮寫。
- `{系列文序號2位}`：使用兩位數流水號，從 `01` 開始。
- 檔案副檔名統一使用 `.md`。

## 新增草稿流程

1. 建立系列主題目錄，例如 `TI_TraceID`。
2. 在系列主題目錄底下建立社群網站目錄，例如 `Linkedin`、`X`、`Medium`。
3. 依照平台與系列縮寫建立 Markdown 草稿，例如 `LTI-01.md`。
4. 同一篇文章若需要在不同平台保留不同版本，請分別放在對應平台目錄中。

## 維護原則

- 每個系列主題都應有清楚且唯一的縮寫。
- 同一系列內的文章序號應連續遞增。
- 不同平台的同一篇文章可使用相同序號，方便比對內容版本。
- 草稿內容以 Markdown 撰寫，便於版本控管與跨平台調整。
